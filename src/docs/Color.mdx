# Color

Colour has two layers. Primitives are the raw palette from Kevin's Figma file. Semantic tokens give each primitive a job (surface, text, border, accent, status). Components use semantic tokens only. They never use a primitive, and they never use a literal value.

Every value on this page is read from the CSS variables in `tokens.css`, so what you see is what ships. The semantic tables show the same variable twice: once under `data-theme="light"` and once under `data-theme="dark"`.

<Rule title="Bind to semantic tokens only">
  Pick a token by what it means, not by which colour it happens to match. A component that uses
  `--he-gray-150` instead of `--he-bg-app` breaks in dark mode. `npm run check:tokens` fails the
  build when component CSS uses a literal colour.
</Rule>

<Rule title="Accent is brand action only, never a status">
  Lime marks the main action and brand moments. It never means success, selected-and-good or
  anything else with a state. Atlassian gives the same advice: do not use an accent colour when the
  colour has semantic meaning.
</Rule>

### Status

Four tones: success, warning, danger and idle. Each has a surface, a border, a text colour and a solid colour. Use surface plus text for badges, and solid for dots and bars.

  same about tags.

## Switching theme

Set `data-theme="dark"` on `<html>`. Do not key on `prefers-color-scheme`. A `.he-theme-dark` class works on a subtree, but it does not reach portalled surfaces such as Menu, Modal, Drawer, Tooltip and Toast, so prefer the attribute.
